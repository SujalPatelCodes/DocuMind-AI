# DocuMind AI — Document Assistant Dashboard (standalone React app)

A pixel-faithful recreation of the AI document-assistant dashboard,
built from the written design spec (React + TypeScript + Tailwind CSS + Lucide).

> Note: the UI is a faithful recreation of the document-assistant dashboard, but the
> **document handling is real** — PDFs are parsed and rendered in the browser
> with `pdf.js` (no backend needed), and chat answers are generated by
> **llama3.2:3b via Ollama** over the PDF's extracted text (retrieval-augmented
> generation with page citations). If Ollama isn't running, the chat falls back
> to the built-in retrieval engine. The original Streamlit app lives in the
> repo root.
>
> Everything is **local and private**: there is no cloud service, no account and
> no telemetry. **Each conversation owns its own PDF** — starting a new chat
> shows an empty viewer you can drop a file into, and one conversation's
> document never leaks into another. Conversations, messages and each PDF are
> persisted to a local **SQLite** file (`data/documind.db`) by a tiny API that
> Vite serves at `/api`, so a page refresh (or a server restart) restores your
> exact workspace.

## Run it

```bash
cd dashboard
npm install
npm run dev      # http://127.0.0.1:5173
```

The chat needs a local Ollama server with the model pulled:

```bash
ollama pull llama3.2:3b
```

In dev, Vite proxies `/ollama/*` to `http://localhost:11434`, so nothing else
is required. For a **production build** (static `dist/`), start Ollama with the
app's origin allowed so the browser can reach it directly:

```bash
OLLAMA_ORIGINS="http://localhost:5173" ollama serve   # or set it in your Ollama config
```

Production build: `npm run build` (output in `dist/`), preview it with
`npm run preview`.

### Persistence (zero extra setup)

The workspace is stored in **SQLite** at `dashboard/data/documind.db` (git-ignored)
through a small REST API mounted at `/api` by a Vite plugin — for both `npm run dev`
and `npm run preview`, on the same origin as the page (no CORS, no extra process
to start). It uses Node's **built-in `node:sqlite`** (Node 22.5+ / 24+), so there
are **no native modules to build and no database to install**. Deleting
`data/documind.db*` resets the app to its first-run sample conversations.

## What's inside

| Component               | Purpose                                                            |
|-------------------------|--------------------------------------------------------------------|
| `App`                   | Full-viewport shell (`h-screen`): the dashboard is the whole website, no outer mockup frame. |
| `AppShell`              | All dashboard state: **per-conversation documents** (parsed with `pdf.js`, lazily reloaded from SQLite), per-conversation chat, model, zoom/search, rails. |
| `NavigationSidebar`     | 44px `#050505` rail: yellow logo, Documents/Code/Upload/Tools, Help/Settings/Profile/Logout, notification badge on the document icon. |
| `ConversationSidebar`   | 220px white rail: search, “+ New Conversation”, TODAY/YESTERDAY groups, selected row `#F1F1F1` with three-dot menu. **Collapsible** — the header chevron shrinks it to a 44px slim rail showing only the expand button and “Conversations” written vertically (bottom → top) in the middle of the strip; no chats are shown while collapsed. |
| `TopHeader`             | 43px header: DocuMind AI branding, centered model selector, Documents button. |
| `ModelSelector`         | Pill group on `#F5F5F7`; active option white pill with purple `#A78BFA` accent. |
| `DocumentToolbar`       | 27px slim bar: “Ask me about {documentName}. View Doc” — the name is live; when the conversation has no PDF it invites you to add one. |
| `PDFViewer`             | **Real PDF rendering** (`pdf.js`): every page is drawn to a canvas that fills the pane width, with a transparent text layer on top so text is selectable and search hits highlight in yellow. **Drag & drop a PDF anywhere in the pane** (or use “Add Document”) to open it into the **active conversation**; when a conversation has no document it shows a drop-zone empty state (with a “Try the sample report” shortcut) and a spinner while a PDF is being read. The document controls strip — zoom, search, select-text, **Add Document** and “Page 1 of N” — sits at the **top** of the pane. **Collapsible like the conversation rail** — a chevron in that strip shrinks it to a 44px slim rail with an expand button and “Opened PDF” written vertically (bottom → top); the chat fills the freed space. |
| `PDFActionToolbar`      | Floating Explain / Summarise / Rewrite buttons → answered from the real page text. |
| `ChatPanel` / `ChatMessage` / `ChatInput` | Spacious `#F8F8F8` chat with yellow avatar, white + black bubbles, copy/thumbs actions, bottom pill input. |
| `pdf.ts`                | `pdf.js` loading + text extraction + canvas/text-layer helpers (`loadPdfDocumentData` parses raw bytes, `loadPdfDocument` wraps a `File`), plus an opt-in runtime-generated sample report (`buildSamplePdf`, via `pdf-lib`). |
| `api.ts`                | Typed client for the local `/api` (state, conversations, messages, settings, per-conversation PDFs). Writes are optimistic and fire-and-forget. |
| `server/apiPlugin.mjs`  | Vite plugin that mounts the `/api` REST routes for both `dev` and `preview` — same origin, no CORS, no second process. |
| `server/store.mjs`      | The SQLite layer (`node:sqlite`, zero dependencies): `conversations`, `messages`, `documents` (PDF BLOBs) and `settings` tables in `data/documind.db`. |
| `qa.ts`                 | Client-side retrieval engine over the extracted text (BM25-lite page scoring, sentence extraction, intent handling). Produces the RAG context quotes and is the offline fallback. |
| `llm.ts`                | Ollama chat client for **llama3.2:3b** (dev proxy `/ollama` first, direct `localhost:11434` second, 90s timeout). |
| `assistant.ts`          | RAG orchestration: builds the model prompt from retrieved excerpts (with page citations), routes “how many pages / summarise” intents, and falls back to `qa.ts` if Ollama is down. |

## Working interactions

- **Open a PDF** — drag & drop a `.pdf` anywhere in the document pane, or use
  any of the three picker affordances: the cloud **Upload** icon in the left
  rail, the header **Documents** button, or the **+ Add Document** button in
  the viewer's top strip. The file is parsed with `pdf.js`, every page is
  extracted, and a confirmation with the real page count is posted to the chat.
  The document belongs to the **active conversation** only.
- **Each conversation has its own PDF** — a new conversation opens with an
  empty viewer, so drop a file in (or click **Try the sample report** to load a
  generated `Energy-Transition-Report-2024.pdf`). Pages render as full-width
  canvases with a selectable text layer; scroll through every page, and
  images/scanned pages fall back gracefully.
- **Chat works on the PDF** — the assistant answers questions with
  **retrieval-augmented generation**: each page is scored against the query
  (BM25-lite), the best sentences are pulled with their page numbers, and
  **llama3.2:3b** (Ollama) writes the answer from those excerpts with page
  citations. It also understands “How many pages…?”, “Summarise the report”,
  and similar, and suggests topics when there's no match. If Ollama is off,
  the built-in engine answers instead.
- Explain / Summarise / Rewrite run through llama3.2:3b too (with the same
  local fallback).
- Search filters conversation history; New Conversation starts a fresh chat with
  an empty document viewer.
- Selecting a conversation switches **both** its chat and its PDF — every
  conversation keeps its own messages and its own document.
- **Nothing is lost on refresh** — conversations, messages, each PDF and the
  active conversation/model are stored in local SQLite and restored on reload.
  Deleting a conversation also deletes its PDF.
- Each conversation row hides a **three-dot button** that appears on hover (and is
  always visible on the active row). Clicking it opens a small **Rename / Delete**
  menu: Rename edits the title inline (Enter/blur saves, Esc cancels), and Delete
  removes the conversation — falling back to the next one, or a fresh chat when
  none remain.
- The model pill shows the active model (**llama3.2:3b**) — every chat request
  is answered by that model through Ollama.
- Zoom in/out rescales the rendered pages; Search highlights every matching
  phrase in the text layer; select-text makes the PDF text selectable.
- Chat input sends on Enter or the send icon (real answer from llama3.2:3b
  over the document; a “Thinking…” bubble shows while the model generates).
- Copy + thumbs-up/down are clickable per message.
- Nav, header and sidebar controls have hover states.
